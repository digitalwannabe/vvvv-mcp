## 1. Document Skeleton

Every `.vl` file must start with this structure. `NugetDependency` is a child of `<Document>`, **never inside `<Patch>`**.

```xml
<?xml version="1.0" encoding="utf-8"?>
<Document xmlns:p="property" xmlns:r="reflection"
          Id="A1b2C3d4E5f6G7h8I9j0Kl"
          LanguageVersion="2025.7.1-0156-gdf75a792b5"
          Version="0.128">

  <!-- Dependencies go HERE, as direct children of Document -->
  <NugetDependency Id="B2c3D4e5F6g7H8i9J0k1Lm" Location="VL.CoreLib"
                   Version="2025.7.1-0156-gdf75a792b5" />

  <Patch Id="C3d4E5f6G7h8I9j0K1l2Mn">
    <!-- Root canvas — FullCategory only here -->
    <Canvas Id="D4e5F6g7H8i9J0k1L2m3No" DefaultCategory="Main"
            BordersChecked="false" CanvasType="FullCategory" />

    <!-- Application is the program entry point -->
    <Node Name="Application" Bounds="100,100" Id="E5f6G7h8I9j0K1l2M3n4Op">
      <p:NodeReference>
        <Choice Kind="ContainerDefinition" Name="Process" />
        <CategoryReference Kind="Category" Name="Primitive" />
      </p:NodeReference>
      <Patch Id="F6g7H8i9J0k1L2m3N4o5Pq">
        <!-- Inner canvas — Group here and everywhere else -->
        <Canvas Id="G7h8I9j0K1l2M3n4O5p6Qr" CanvasType="Group">
          <!-- Nodes, Pads go here -->
        </Canvas>
        <Patch Id="H8i9J0k1L2m3N4o5P6q7Rs" Name="Create" />
        <Patch Id="I9j0K1l2M3n4O5p6Q7r8St" Name="Update" />
        <ProcessDefinition Id="J0k1L2m3N4o5P6q7R8s9Tu">
          <Fragment Id="K1l2M3n4O5p6Q7r8S9t0Uv"
                   Patch="H8i9J0k1L2m3N4o5P6q7Rs" Enabled="true" />
          <Fragment Id="L2m3N4o5P6q7R8s9T0u1Vw"
                   Patch="I9j0K1l2M3n4O5p6Q7r8St" Enabled="true" />
        </ProcessDefinition>
        <!-- Links go here, inside the inner Patch -->
      </Patch>
    </Node>
  </Patch>
</Document>
```

**Critical rules:**
- `xmlns:p="property"` must be on `<Document>` — missing it breaks everything silently
- `Version="0.128"` always required
- All IDs: 22-character base62 `[A-Za-z0-9]` — generate fresh ones for every element
- Inner canvases use `CanvasType="Group"`, never `FullCategory`
- Links go inside the inner `<Patch>`, not inside `<Canvas>`

## 2. Nodes and Connections

### Operation (stateless, pure function)

```xml
<Node Bounds="300,300,65,19" Id="...">
  <p:NodeReference LastCategoryFullName="Math" LastDependency="VL.CoreLib.vl">
    <Choice Kind="NodeFlag" Name="Node" Fixed="true" />
    <Choice Kind="OperationCallFlag" Name="+" />
  </p:NodeReference>
  <Pin Id="pinA_id" Name="Input"   Kind="InputPin" />
  <Pin Id="pinB_id" Name="Input 2" Kind="InputPin" />
  <Pin Id="pinOut_id" Name="Output" Kind="OutputPin" />
</Node>
```

### Stateful Process (has state, Create+Update lifecycle)

```xml
<Node Bounds="300,300,45,19" Id="...">
  <p:NodeReference LastCategoryFullName="Animation" LastDependency="VL.CoreLib.vl">
    <Choice Kind="NodeFlag" Name="Node" Fixed="true" />
    <Choice Kind="ProcessAppFlag" Name="LFO" />
  </p:NodeReference>
  <Pin Id="period_pin" Name="Period"      Kind="InputPin" DefaultValue="2" />
  <Pin Id="pause_pin"  Name="Pause"       Kind="InputPin" />
  <Pin Id="reset_pin"  Name="Reset"       Kind="ApplyPin" />
  <Pin Id="phase_pin"  Name="Phase"       Kind="OutputPin" />
  <Pin Id="cycle_pin"  Name="On New Cycle" Kind="OutputPin" />
</Node>
```

### Link (output pin ID first, input pin ID second)

```xml
<Link Id="..." Ids="outputPinId,inputPinId" />
```

## 3. IOBox (Pad) Patterns

All IOBoxes use `isIOBox="true"` (lowercase `i`).

```xml
<!-- Float32 -->
<Pad Id="..." Bounds="200,230,35,15" ShowValueBox="true" isIOBox="true"
     Value="1.0" Comment="Amount">
  <p:TypeAnnotation LastCategoryFullName="Primitive" LastDependency="VL.CoreLib.vl">
    <Choice Kind="TypeFlag" Name="Float32" />
  </p:TypeAnnotation>
</Pad>

<!-- Integer32 -->
<Pad Id="..." Bounds="200,230,35,15" ShowValueBox="true" isIOBox="true"
     Value="5" Comment="Count">
  <p:TypeAnnotation LastCategoryFullName="Primitive" LastDependency="VL.CoreLib.vl">
    <Choice Kind="TypeFlag" Name="Integer32" />
  </p:TypeAnnotation>
</Pad>

<!-- Boolean toggle (checkbox) -->
<Pad Id="..." Bounds="200,230,35,35" ShowValueBox="true" isIOBox="true"
     Value="False" Comment="Enable">
  <p:TypeAnnotation LastCategoryFullName="Primitive" LastDependency="VL.CoreLib.vl">
    <Choice Kind="ImmutableTypeFlag" Name="Boolean" />
  </p:TypeAnnotation>
</Pad>

<!-- Boolean bang (momentary) — add ValueBoxSettings -->
<Pad Id="..." Bounds="200,230,35,35" ShowValueBox="true" isIOBox="true"
     Value="False" Comment="Trigger">
  <p:TypeAnnotation LastCategoryFullName="Primitive" LastDependency="VL.CoreLib.vl">

  <p:TypeAnnotation LastCategoryFullName="Primitive" LastDependency="VL.CoreLib.vl">

<!-- Vector3 (x,y,z) -->

  <p:TypeAnnotation LastCategoryFullName="3D" LastDependency="VL.CoreLib.vl">
    <Choice Kind="TypeFlag" Name="Vector3" />
  </p:TypeAnnotation>

<!-- Color RGBA -->
<Pad Id="..." Bounds="200,230,136,15" ShowValueBox="true" isIOBox="true"

<!-- Spread<RGBA> — multi-value display -->
<Pad Id="..." Bounds="200,230,141,95" ShowValueBox="true" isIOBox="true">
  <p:TypeAnnotation LastCategoryFullName="Collections" LastDependency="VL.CoreLib.vl">
    <Choice Kind="TypeFlag" Name="Spread" />
    <p:TypeArguments>
      <TypeReference LastCategoryFullName="Color" LastDependency="VL.CoreLib.vl">
        <Choice Kind="TypeFlag" Name="RGBA" />
      </TypeReference>
    </p:TypeArguments>
  </p:TypeAnnotation>
  <p:Value>
    <Item>1, 0, 0, 1</Item>
    <Item>0, 1, 0, 1</Item>
    <Item>0, 0, 1, 1</Item>
  </p:Value>
</Pad>
```

## 4. Region Patterns

### If Region

Patches: `Create` + `Then`. For If/Else use two If regions with a `NOT` node.
Data crosses the boundary via `ControlPoint` splicers (Top = input, Bottom = output).

```xml
<!-- Outside: condition pad at y=270 -->
<Pad Id="condPad" Bounds="200,270,35,35" ShowValueBox="true" isIOBox="true"
     Value="False" Comment="Condition">
  <p:TypeAnnotation LastCategoryFullName="Primitive" LastDependency="VL.CoreLib.vl">
    <Choice Kind="ImmutableTypeFlag" Name="Boolean" />
  </p:TypeAnnotation>
  <p:ValueBoxSettings>
    <p:buttonmode p:Assembly="VL.UI.Forms"
                  p:Type="VL.HDE.PatchEditor.Editors.ButtonModeEnum">Press</p:buttonmode>
  </p:ValueBoxSettings>
</Pad>

<!-- Input pad flowing through the region -->
<Pad Id="inPad" Bounds="200,230,35,15" ShowValueBox="true" isIOBox="true"
     Value="0">
  <p:TypeAnnotation LastCategoryFullName="Primitive" LastDependency="VL.CoreLib.vl">
    <Choice Kind="TypeFlag" Name="Float32" />
  </p:TypeAnnotation>
</Pad>

<!-- If region node: Bounds="X,Y,W,H" — give it enough height for content -->
<Node Bounds="180,330,200,120" Id="ifNodeId">
  <p:NodeReference LastCategoryFullName="Primitive" LastDependency="Builtin">
    <Choice Kind="StatefulRegion" Name="Region (Stateful)" Fixed="true" />
    <CategoryReference Kind="Category" Name="Primitive" />
    <Choice Kind="ApplicationStatefulRegion" Name="If" />
  </p:NodeReference>
  <Pin Id="condPin" Name="Condition" Kind="InputPin" />
  <Patch Id="ifInnerPatch" ManuallySortedPins="true">
    <Patch Id="ifCreate" Name="Create" ManuallySortedPins="true" />
    <Patch Id="ifThen"   Name="Then"   ManuallySortedPins="true" />
    <!-- Node to execute when condition is true -->
    <Node Bounds="200,360,65,19" Id="thenNode">
      <p:NodeReference LastCategoryFullName="Animation" LastDependency="VL.CoreLib.vl">
        <Choice Kind="NodeFlag" Name="Node" Fixed="true" />
        <Choice Kind="ProcessAppFlag" Name="LFO" />
      </p:NodeReference>
      <Pin Id="thenInput"  Name="Period" Kind="InputPin" />
      <Pin Id="thenOutput" Name="Phase"  Kind="OutputPin" />
    </Node>
  </Patch>
  <!-- Splicers: Top = input boundary, Bottom = output boundary -->
  <ControlPoint Id="ifTopSplicer"    Bounds="194,336" Alignment="Top" />
  <ControlPoint Id="ifBottomSplicer" Bounds="194,444" Alignment="Bottom" />
</Node>

<!-- Output pad below the region -->
<Pad Id="outPad" Bounds="200,480,35,15" ShowValueBox="true" isIOBox="true">
  <p:TypeAnnotation LastCategoryFullName="Primitive" LastDependency="VL.CoreLib.vl">
    <Choice Kind="TypeFlag" Name="Float32" />
  </p:TypeAnnotation>
</Pad>

<!-- Links (all at the outer Patch level) -->
<Link Id="..." Ids="condPad,condPin" />           <!-- condition to If -->
<Link Id="..." Ids="inPad,ifTopSplicer" />         <!-- input into region -->
<Link Id="..." Ids="ifTopSplicer,thenInput" />     <!-- inside: access input -->
<Link Id="..." Ids="thenOutput,ifBottomSplicer" /> <!-- inside: emit output -->
<Link Id="..." Ids="ifBottomSplicer,outPad" />     <!-- output out of region -->
```

### ForEach Region

Iterates a `Spread<T>`, producing a `Spread<U>`. Each element flows in via the Top splicer, result flows out via the Bottom splicer. Patches: `Create` + `Update` + `Dispose`.

```xml
<!-- Spread input at y=280 -->
<Pad Id="spreadIn" Bounds="60,280,35,15" ShowValueBox="true" isIOBox="true">
  <p:TypeAnnotation LastCategoryFullName="Collections" LastDependency="VL.CoreLib.vl">
    <Choice Kind="TypeFlag" Name="Spread" />
    <p:TypeArguments>
      <TypeReference LastCategoryFullName="Primitive" LastDependency="VL.CoreLib.vl">
        <Choice Kind="TypeFlag" Name="Float32" />
      </TypeReference>
    </p:TypeArguments>
  </p:TypeAnnotation>
  <p:Value>
    <Item>1</Item><Item>2</Item><Item>3</Item>
  </p:Value>
</Pad>

<Node Bounds="40,320,200,180" Id="forEachId">
  <p:NodeReference LastCategoryFullName="Primitive" LastDependency="Builtin">
    <Choice Kind="StatefulRegion" Name="Region (Stateful)" Fixed="true" />
    <Choice Kind="ApplicationStatefulRegion" Name="ForEach" />
    <CategoryReference Kind="Category" Name="Primitive" />
  </p:NodeReference>
  <Pin Id="breakPin" Name="Break" Kind="OutputPin" />
  <Patch Id="forEachInner" ManuallySortedPins="true">
    <Patch Id="feCreate"  Name="Create"  ManuallySortedPins="true" />
    <Patch Id="feUpdate"  Name="Update"  ManuallySortedPins="true" />
    <Patch Id="feDispose" Name="Dispose" ManuallySortedPins="true" />
    <!-- Process each element: multiply by 2 -->
    <Node Bounds="54,380,22,19" Id="mulNode">
      <p:NodeReference LastCategoryFullName="Adaptive" LastDependency="VL.CoreLib.vl">
        <Choice Kind="NodeFlag" Name="Node" Fixed="true" />
        <Choice Kind="OperationCallFlag" Name="* (Scale)" />
      </p:NodeReference>
      <Pin Id="mulIn"     Name="Input"  Kind="InputPin" />
      <Pin Id="mulScalar" Name="Scalar" Kind="InputPin" DefaultValue="2" />
      <Pin Id="mulOut"    Name="Output" Kind="OutputPin" />
    </Node>
  </Patch>
  <ControlPoint Id="feTop"    Bounds="54,326" Alignment="Top" />
  <ControlPoint Id="feBottom" Bounds="54,494" Alignment="Bottom" />
</Node>

<!-- Output pad collects the spread of results -->
<Pad Id="spreadOut" Bounds="42,530,35,15" ShowValueBox="true" isIOBox="true">
  <p:TypeAnnotation LastCategoryFullName="Collections" LastDependency="VL.CoreLib.vl">
    <Choice Kind="TypeFlag" Name="Spread" />
    <p:TypeArguments>
      <TypeReference LastCategoryFullName="Primitive" LastDependency="VL.CoreLib.vl">
        <Choice Kind="TypeFlag" Name="Float32" />
      </TypeReference>
    </p:TypeArguments>
  </p:TypeAnnotation>
</Pad>

<Link Id="..." Ids="spreadIn,feTop" />      <!-- spread → region input -->
<Link Id="..." Ids="feTop,mulIn" />          <!-- inside: element → node -->
<Link Id="..." Ids="mulOut,feBottom" />      <!-- inside: result → output -->
<Link Id="..." Ids="feBottom,spreadOut" />   <!-- region output → pad -->
```

## 6. Channel / Reactive Patterns

Channels are observable values — they push notifications when their value changes. Unlike regular dataflow, channels decouple producers from consumers.

### Create and use a Channel

```xml
<!-- Channel node: wraps a value in an observable container -->
<Node Bounds="300,200,53,19" Id="chanNodeId">
  <p:NodeReference LastCategoryFullName="Reactive" LastDependency="VL.CoreLib.vl">
    <Choice Kind="NodeFlag" Name="Node" Fixed="true" />
    <Choice Kind="ProcessAppFlag" Name="Channel" />
  </p:NodeReference>
  <Pin Id="chanValIn"  Name="Value"  Kind="InputPin" />    <!-- initial value -->
  <Pin Id="chanOutput" Name="Output" Kind="OutputPin" />   <!-- the IChannel<T> -->
  <Pin Id="chanValOut" Name="Value"  Kind="OutputPin" />   <!-- current value (polling) -->
</Node>

<!-- SetValue: push a new value into the channel imperatively -->
<Node Bounds="300,280,55,26" Id="setValId">
  <p:NodeReference LastCategoryFullName="Reactive.Channel" LastDependency="VL.CoreLib.vl">
    <Choice Kind="NodeFlag" Name="Node" Fixed="true" />
    <CategoryReference Kind="ClassType" Name="Channel" NeedsToBeDirectParent="true" />
    <Choice Kind="OperationCallFlag" Name="SetValue" />
  </p:NodeReference>
  <Pin Id="svIn"    Name="Input"  Kind="StateInputPin" />  <!-- the channel -->
  <Pin Id="svVal"   Name="Value"  Kind="InputPin" />       <!-- new value -->
  <Pin Id="svApply" Name="Apply"  Kind="InputPin" />       <!-- bang to trigger -->
  <Pin Id="svOut"   Name="Output" Kind="StateOutputPin" />
</Node>

<!-- Value: read the current value from a channel each frame -->
<Node Bounds="300,340,45,26" Id="getValId">
  <p:NodeReference LastCategoryFullName="Reactive.Channel" LastDependency="VL.CoreLib.vl">
    <Choice Kind="NodeFlag" Name="Node" Fixed="true" />
    <CategoryReference Kind="ClassType" Name="Channel" NeedsToBeDirectParent="true" />
    <Choice Kind="OperationCallFlag" Name="Value" />
  </p:NodeReference>
  <Pin Id="gvIn"    Name="Input"  Kind="StateInputPin" />
  <Pin Id="gvOut"   Name="Output" Kind="StateOutputPin" />
  <Pin Id="gvValue" Name="Value"  Kind="OutputPin" />
</Node>

<!-- EnsureValue: set a default only if no value has been pushed yet -->
<Node Bounds="300,400,72,26" Id="ensureId">
  <p:NodeReference LastCategoryFullName="Reactive.Channel" LastDependency="VL.CoreLib.vl">
    <Choice Kind="NodeFlag" Name="Node" Fixed="true" />
    <CategoryReference Kind="ClassType" Name="Channel" NeedsToBeDirectParent="true" />
    <Choice Kind="OperationCallFlag" Name="EnsureValue" />
  </p:NodeReference>
  <Pin Id="evIn"    Name="Input"  Kind="StateInputPin" />
  <Pin Id="evVal"   Name="Value"  Kind="InputPin" />
  <Pin Id="evForce" Name="Force"  Kind="InputPin" />
</Node>

<!-- Typical wiring -->
<Link Id="..." Ids="initialValuePad,chanValIn" />
<Link Id="..." Ids="chanOutput,svIn" />    <!-- same channel into SetValue -->
<Link Id="..." Ids="newValuePad,svVal" />
<Link Id="..." Ids="bangPad,svApply" />
<Link Id="..." Ids="chanOutput,gvIn" />    <!-- same channel into Value -->
<Link Id="..." Ids="gvValue,resultPad" />
```

### Observable → Consume (Channel) pattern

Convert any IObservable into a Channel. Each time the observable emits, the channel gets updated.

```xml

  <Pin Id="toObsSend" Name="Send"    Kind="InputPin" />
  <Pin Id="toObsOut"  Name="Result"  Kind="OutputPin" />

<!-- Consume: subscribes to an observable and pushes values into a channel -->
<Node Bounds="400,260,59,19" Id="consumeId">
  <p:NodeReference LastCategoryFullName="Reactive.Channel" LastDependency="VL.CoreLib.vl">
    <Choice Kind="NodeFlag" Name="Node" Fixed="true" />

  <Pin Id="consChanA" Name="Channel A" Kind="InputPin" />  <!-- the channel to write to -->

  <Pin Id="consOut"   Name="Output"   Kind="OutputPin" />
</Node>

<Link Id="..." Ids="lfoPhase,toObsMsg" />
<Link Id="..." Ids="bangPad,toObsSend" />
<Link Id="..." Ids="chanOutput,consChanA" />
<Link Id="..." Ids="toObsOut,consChanB" />
```

## 10. SDSL Shader Patterns

### TextureFX Filter (per-pixel transformation)

File naming: `MyName_TextureFX.sdsl` → vvvv auto-creates a "MyName" node.

```hlsl
[Category("Filter")]
[Summary("Describe what the filter does")]
shader MyEffect_TextureFX : FilterBase
{
    // Uniform parameters become node input pins automatically
    float Intensity = 1.0f;
    
    [Color]
    float4 Tint = float4(1, 1, 1, 1);

    // tex0col is the sampled input texture color at the current pixel
    float4 Filter(float4 tex0col)
    {
        return tex0col * Tint * Intensity;
    }
};  // semicolon after closing brace is REQUIRED
```

### TextureFX Mixer (blend two textures)

```hlsl
[Category("Mixer")]
[Summary("Blend two textures")]
shader MyMix_TextureFX : MixerBase
{
    // Receives two input textures and a fader [0..1]
    float4 Mix(float4 tex0col, float4 tex1col, float fader)
    {
        return lerp(tex0col, tex1col, fader);
    }
};
```

### TextureFX Source (procedural — no input texture)

```hlsl
[TextureSource]
[Category("Source")]
[Summary("Generate pixels procedurally")]
shader MySource_TextureFX : TextureFX
{
    [Color]
    float4 Color = float4(1, 1, 1, 1);

    stage override float4 Shading()
    {
        // streams.TexCoord gives UV [0..1], streams.ShadingPosition for clip position
        return Color;
    }
};
```

### ComputeFX (GPU compute)

```hlsl
[Summary("Compute shader")]
shader MyCompute_ComputeFX : ComputeShaderBase
{
    float Constant = 1.0f;
    RWBuffer<float> Values;

    override void Compute()
    {
        uint index = streams.DispatchThreadId.x;
        Values[index] *= Constant;
    }
};
```

### DrawFX (vertex + pixel shader)

```hlsl
[Summary("Custom draw shader")]
shader MyDraw_DrawFX : VS_PS_Base, ColorBase, ShaderUtils
{
    // VS_PS_Base already includes: Transformation, NormalStream, PositionStream4
    // DO NOT re-inherit these — it causes compilation errors

    [Color]
    stage float4 ColorInput = float4(1, 1, 1, 1);

    override stage void VSMain()
    {
        // Transform vertex to clip space
        streams.ShadingPosition = mul(streams.Position, WorldViewProjection);
    }

    override stage void PSMain()
    {
        streams.ColorTarget = ColorInput;
    }
};
```

**SDSL critical rules:**
- Semicolon after `};` — required
- `stage` members are shared across compositions (declare once, use everywhere)
- `stream` members flow between pipeline stages automatically
- `override` is required to replace parent methods
- `VS_PS_Base` already includes `Transformation` — do not inherit it again

## 11. Layout Conventions (from VL.StandardLibs analysis)

All coordinates are pixels from top-left. Data flows **top to bottom**.

| Element | Typical Y-position |
|---|---|
| Title comment (font=14) | ~100 |
| Description comment (font=9) | ~140–190 |
| Input Pads | ~200–270 |
| Processing nodes | ~300–400 |
| Output Pads | ~420–500 |
| Skia/Stride Renderer | ~800+ |

| Spacing | Value |
|---|---|
| Input Pad → Node below | 50–80 px |
| Node → Node (chain) | 40–50 px |
| Node → Output Pad | 60–70 px |
| Multiple sections side-by-side | 350–400 px gap |

| Size | Typical |
|---|---|
| Standard node | `65,19` or `85,19` |
| Simple operator (+, *, …) | `22,19` or `25,19` |
| Float32 Pad | `35,15` |
| Boolean Pad (toggle/bang) | `35,35` |
| String comment | `300,25` (title) or `300,40` (description) |

**Multi-input staircase**: when N pads feed one node, offset each pad by (+27x, +29y) so links don't cross.

**Bounds format**: definition nodes (Application, Process) use `"X,Y"` (2-value); operational nodes and Pads use `"X,Y,W,H"` (4-value).
